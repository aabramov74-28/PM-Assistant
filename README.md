# Ассистент PM (MVP)

ИИ-агент координации проектного офиса: задачи и сроки в Telegram-боте,
напоминания и эскалации, сбор статусов от исполнителей, дайджесты и отчёты.
Техническое задание: `ТЗ_MVP_Ассистент_PM.docx`.

## Стек

Python 3.11+, python-telegram-bot (JobQueue), SQLite, python-docx.
Интеграции (недели 3–4 плана ТЗ): корпоративная почта (IMAP/SMTP),
Яндекс 360 Календарь (CalDAV), LLM через OpenAI-совместимый API.

## Запуск

```bash
# 1. Окружение
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Конфигурация
cp .env.example .env
# В .env заполните TELEGRAM_BOT_TOKEN (получить у @BotFather)
# и ADMIN_TG_IDS (свой Telegram ID — узнать у @userinfobot)

# 3. Старт
python main.py
```

Первый, кто указан в `ADMIN_TG_IDS`, автоматически получает роль `admin`
при регистрации через `/start` — дальше команда добавляется двумя способами:
самостоятельная регистрация через `/start` или приглашение от PM (`/addmember`).

## Онбординг команды

PM может зарегистрировать участника заранее: `/addmember` → имя, @username,
e-mail, роль. Бот создаёт карточку и персональную ссылку-приглашение
(`t.me/<бот>?start=inv_...`). Участник переходит по ней один раз — его
Telegram привязывается к карточке автоматически. Бот не может написать
пользователю первым, поэтому ссылку PM отправляет любым каналом.
Неактивированный участник уже виден в списках и может быть назначен
исполнителем (помечается «⏳»); до активации напоминания идут на e-mail,
если он указан. Ссылка одноразовая — после активации токен гасится.

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | регистрация (имя, e-mail, роль) |
| `/newproject CODE Название` | PM | создать проект |
| `/addmember` | PM | добавить участника: имя, @username, e-mail, роль → ссылка-приглашение |
| `/settings` | PM | частота проверок исполнения и отчётов по проекту |
| `/newtask` | PM | мастер постановки задачи (проект → название → описание → исполнитель → дедлайн → приоритет) |
| `/mytasks` | все | мои активные задачи |
| `/tasks` | PM | активные задачи портфеля |
| `/status TASK-NNN [текст]` | исполнитель | обновить статус (свободный текст разбирает LLM; без LLM — сохраняется как комментарий) |
| `/done TASK-NNN` | исполнитель | отметить готовность → статус «На проверке» |
| `/extend TASK-NNN ДД.ММ.ГГГГ причина` | исполнитель | запрос переноса срока (PM подтверждает кнопкой) |
| `/digest` | PM | дайджест немедленно |
| `/report` | PM | статус-отчёт .docx за текущую неделю |

## Расписания (настраиваются в .env)

| Задание | Время по умолчанию | Содержание |
|---|---|---|
| Проверка сроков | 08:30 ежедневно | напоминания и эскалации по матрице (раздел 5.2 ТЗ) |
| Дайджест PM | 09:00 ежедневно | выполнено / просрочки / дедлайны 3 дней / зависшие / эскалации |
| Вечерний опрос | 18:00 по будням | сбор статусов — в дни проверки каждого проекта (`check_frequency`) |
| Отчёты по проектам | 17:00 по будням | .docx по проекту — в дни его `report_frequency` (Telegram + e-mail) |
| Почтовый опрос | каждые 15 минут | приём ответов исполнителей по e-mail |
| Синхронизация CalDAV | каждые 30 минут | повторные попытки по несинхронизированным задачам |

Часовой пояс: `TZ` в .env (по умолчанию Europe/Moscow).

## Расписания по проектам

У каждого проекта — своя частота **проверок исполнения** (опрос исполнителей)
и **генерации отчётов** (.docx). Настраивается PM через `/settings`:
выбор проекта → кнопки частоты. Варианты:

| Частота | Дни срабатывания | Период отчёта |
|---|---|---|
| 1 раз/день | будни (Пн–Пт) | 1 день |
| 2 раза/нед | Вт и Пт | 4 дня |
| 1 раз/нед | Пт | 7 дней |

По умолчанию для новых проектов: проверки — каждый день, отчёты — раз в неделю.
Изменения фиксируются в журнале аудита. Напоминания по дедлайнам от расписания
проекта не зависят — они привязаны к датам самих задач.

## Подключение почты (IMAP/SMTP)

Модуль уже встроен (раздел 5.6 ТЗ):

- **Отправка** — дайджесты и недельные отчёты (.docx во вложении) PM,
  напоминания исполнителям без Telegram. Порт 465 — SSL, 587 — STARTTLS.
- **Приём** — каждые 15 минут читаются непрочитанные ответы с тегом
  `[TASK-NNN]` в теме, текст разбирается LLM и обновляет статус задачи.
  Неразобранные ответы сохраняются комментарием и пересылаются PM (FR-26).
  Чужие письма не открываются, письма не удаляются.

Активация: заполните `SMTP_*` и `IMAP_*` в `.env` и перезапустите сервис.
Для корпоративных ящиков с двухфакторной аутентификацией обычно нужен
пароль приложения. Без настроек отправки пропускаются и пишутся
в журнал аудита.

## Подключение календаря (Яндекс 360, CalDAV)

Модуль уже встроен (раздел 5.5 ТЗ):

- **Создание задачи → событие-дедлайн** в календаре (FR-21): название,
  код задачи, исполнитель.
- **Перенос срока → событие обновляется** по тому же UID (FR-22).
- **Отказоустойчивость (FR-23)**: при недоступности CalDAV задача остаётся
  в очереди и досинхронизируется автоматически — планировщик повторяет
  попытку каждые 30 минут, сбои пишутся в журнал аудита.

Активация: создайте пароль приложения (Яндекс ID → Безопасность →
Пароли приложений → «Календарь»), заполните `CALDAV_USER` (полный адрес
вида `user@company.ru` для Яндекс 360) и `CALDAV_PASSWORD` в `.env`,
перезапустите сервис. Проверка связи:
`python -c "from app.integrations.calendar_sync import CalendarSync; print(CalendarSync().healthcheck())"`

MVP использует первый календарь аккаунта. Отдельный календарь на проект —
через поле `caldav_calendar_id` в таблице проектов (URL календаря).

## Подключение LLM (YandexGPT)

Модуль уже встроен: разбор свободных ответов в `/status` и резюме в дайджесте
и недельном отчёте. Чтобы активировать:

1. В Yandex Cloud создайте сервисный аккаунт с ролью `ai.languageModels.user`
   и выпустите API-ключ.
2. Заполните в `.env`: `LLM_API_KEY`, `LLM_FOLDER_ID` (ID каталога) и
   `LLM_MODEL=gpt://<folder_id>/yandexgpt-lite/latest`.
3. Перезапустите сервис. Проверка связи:
   `python -c "from app.integrations.llm import LLMModule; print(LLMModule().healthcheck())"`

Без ключей или при сбое API агент работает в деградированном режиме:
свободные ответы сохраняются как комментарии и уходят PM на разбор,
дайджест и отчёт формируются по шаблонам (FR-29).

## Поведение без настроенных интеграций

MVP устойчив к отсутствию модулей (FR-23, FR-26, FR-29 ТЗ):

- без почты — отправки пропускаются и пишутся в журнал аудита;
- без CalDAV — задачи работают, события в календаре не создаются;
- без LLM — свободные ответы сохраняются как комментарии и уходят PM на разбор.
